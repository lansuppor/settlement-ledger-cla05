# 业务规则

## 订单

- 订单以（租户, 订单标识）唯一；重复受理必须被拒绝且不改变已存在单据。
- 未收金额 = 订单金额 − 已收金额；收款不得超过未收金额。
- 跨租户读取一律按“不存在”处理，不得泄漏对象是否存在。
- 金额以最小货币单位的整数表示，不使用浮点数。

## 退款单

- 退款单以（租户, 订单标识, 退款单标识）唯一；同一订单可有多个不同标识的退款单，同一标识重复受理必须拒绝（409），且不改变已存在退款单或订单的金额与状态。
- 退款金额必须为最小货币单位正整数；订单不存在（含跨租户）受理按不存在处理（404）。
- 可退余额守恒：任意时刻，同一订单所有“待处理 + 已完成”退款单金额之和不得超过订单已收金额。受理即占用余额；撤销释放占用；完成把占用转为实际扣减；冲正把款项加回已收。超限受理拒绝（409），不留部分写入。
- 状态机：`pending`（待处理，受理后）→ `completed`（已完成）或 `cancelled`（已撤销）；`completed` → `reversed`（已冲正，冲正仅限一次）。
  - 完成：按退款单金额扣减订单已收，未收金额同步增加；`effective_deduction_cents` 记为退款金额。
  - 撤销：不扣减订单金额，释放余额占用。
  - 冲正：把已扣减金额加回订单已收，`effective_deduction_cents` 归零，进入终态。
  - 每张退款单只能到达一个终态；对终态重复推进、已完成再撤销、非已完成冲正、重复冲正一律拒绝（409）且不改变数据。
- 受理、推进、冲正均须携带 `request_id`；同一请求标识重放同一操作返回与首次完全一致的结果，不重复扣减、不重复释放。
- 退款单与订单两侧的金额变动在同一事务内原子生效或都不生效；并发下以写事务串行化保证不超额退款。
- 按标识读取、按订单列出均须携带租户头；跨租户读取、列出、操作一律 404，不泄漏对象是否存在。
