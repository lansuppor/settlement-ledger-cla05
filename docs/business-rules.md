# 业务规则

## 订单

- 订单以（租户, 订单标识）唯一；重复受理必须被拒绝且不改变已存在单据。
- 未收金额 = 订单金额 − 已收金额；收款不得超过未收金额。
- 跨租户读取一律按“不存在”处理，不得泄漏对象是否存在。
- 金额以最小货币单位的整数表示，不使用浮点数。

## 退款单

- 退款单以（租户, 订单标识, 退款单标识）唯一；同一订单可有多张不同标识的退款单，同一标识重复受理必须拒绝且不改变已存在退款单或订单的金额与状态。
- 可退余额守恒：任一时刻「待处理退款单金额之和 + 已生效退款扣减」不得超过订单已收金额。受理即占用，撤销释放占用；超限请求拒绝且不留部分写入。
- 状态机：受理后 `pending`；可推进一次到 `completed`（实际退款，扣减订单已收并同步未收）或 `cancelled`（释放占用、不扣减）。终态重复推进或再推进一律拒绝；已完成不可撤销。
- 冲正：`completed` 可冲正一次，金额加回订单已收，进入 `reversed` 终态且当前生效扣减清零；订单与退款单两侧原子生效。冲正后不可撤销或重复冲正。
- 当前生效扣减：`completed` 为退款金额，其余状态为 0；冲正后该订单上对应金额重新可退。
- 幂等：受理、推进、冲正各自携带 `request_id`；同标识重放返回首次结果（含失败响应），不重复扣减或释放；同标识改作不同操作/对象返回 409。
- 并发：所有写操作在单库写事务内串行提交（`BEGIN IMMEDIATE`），竞争同一余额时超限者失败，绝不超额退款或重复扣减。
- 隔离：读取、列表与全部操作均以 `X-Tenant` 限定；跨租户一律按不存在（404）处理，不泄漏对象是否存在。
- 持久化：全部状态与幂等记录落库；中断在事务中的请求重试后要么完整生效要么完全不生效。
