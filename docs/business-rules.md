# 业务规则

## 订单

- 订单以（租户, 订单标识）唯一；重复受理必须被拒绝且不改变已存在单据。
- 未收金额 = 订单金额 − 已收金额 − 进行中结算单核销金额之和；收款不得超过未收金额。
- 跨租户读取一律按“不存在”处理，不得泄漏对象是否存在。
- 金额以最小货币单位的整数表示，不使用浮点数。

## 结算单

- 结算单针对已存在订单发起，以（租户, 订单标识, 结算单标识）唯一；同一订单同一标识重复受理必须拒绝且不改变任何数据。受理参数：核销金额（最小货币单位正整数）、事由说明（非空文本）。
- 未收金额守恒：未收金额 = 订单金额 − 已收金额 − 进行中（待核销）结算单核销金额之和（撤销/冲正即释放或加回）。受理即占用未收余额；订单收款同样不得侵占该占用。超限请求拒绝且不留部分写入。
- 状态机：受理后 `pending`；可推进一次到 `settled`（核销金额计入订单已收并同步未收，订单与结算单同事务原子生效）或 `cancelled`（释放占用、不动订单金额）。终态不可再推进，重复推进一律拒绝；已核销不可撤销。
- 冲正：`settled` 可冲正一次，核销金额从订单已收减回、未收同步加回，进入 `reversed` 终态；订单与结算单两侧原子生效。冲正后不可撤销或重复冲正。
- 当前生效扣减：`settled` 为核销金额，其余状态为 0。
- 幂等：受理、推进、冲正各自携带 `request_id`；同标识重放返回首次结果（含失败响应），不重复占用、扣减或释放；同标识改作不同操作/对象返回 409。
- 并发：全部写操作在单库 `BEGIN IMMEDIATE` 事务内串行提交，核销/冲正以条件更新兜底；竞争同一未收余额时超限者失败，绝不超额核销或重复扣减。
- 检索：支持按订单列出全部结算单，以及按状态与核销金额范围检索当前租户结算单，均按受理先后稳定排序。
- 隔离：单读、列表、检索与全部操作均以 `X-Tenant` 限定；跨租户一律按不存在（404）处理，不泄漏对象是否存在。
- 持久化：结算单状态、订单金额与占用关系、幂等记录全部落库；中断在事务中的请求重试后要么完整生效要么完全不生效。

## 退款单

- 退款单以（租户, 订单标识, 退款单标识）唯一；同一订单可有多张不同标识的退款单，同一标识重复受理必须拒绝且不改变已存在退款单或订单的金额与状态。
- 可退余额守恒：任一时刻「待处理退款单金额之和 + 已生效退款扣减」不得超过订单已收金额。受理即占用，撤销释放占用；超限请求拒绝且不留部分写入。
- 状态机：受理后 `pending`；可推进一次到 `completed`（实际退款，扣减订单已收并同步未收）或 `cancelled`（释放占用、不扣减）。终态重复推进或再推进一律拒绝；已完成不可撤销。
- 冲正：`completed` 可冲正一次，金额加回订单已收，进入 `reversed` 终态且当前生效扣减清零；订单与退款单两侧原子生效。冲正后不可撤销或重复冲正。
- 当前生效扣减：`completed` 为退款金额，其余状态为 0；冲正后该订单上对应金额重新可退。
- 幂等：受理、推进、冲正各自携带 `request_id`；同标识重放返回首次结果（含失败响应），不重复扣减或释放；同标识改作不同操作/对象返回 409。
- 并发：所有写操作在单库写事务内串行提交（`BEGIN IMMEDIATE`），竞争同一余额时超限者失败，绝不超额退款或重复扣减。
- 隔离：读取、列表与全部操作均以 `X-Tenant` 限定；跨租户一律按不存在（404）处理，不泄漏对象是否存在。
- 持久化：全部状态与幂等记录落库；中断在事务中的请求重试后要么完整生效要么完全不生效。

## 工单

- 工单针对已存在退款单发起，以（租户, 订单标识, 退款单标识, 工单标识）唯一；同一工单标识重复受理必须拒绝且不改变任何数据。受理参数：处理请求金额（最小货币单位正整数）、发起人代号、事由说明（非空文本）。
- 仅 `pending` 与 `completed` 的退款单可被工单受理；`cancelled`、`reversed` 的退款单不可再被受理。
- 处理中标记：受理即对退款单施加标记，一张退款单最多被一张进行中（已受理/处理中/待复核）工单标记，重复标记拒绝且不改数据（数据库部分唯一索引兜底并发）。工单进行中期间，退款单的完成、撤销、冲正一律拒绝。工单终态（已解决/已撤销）释放标记，同一退款单可再开新工单。
- 工单受理不改变订单与退款单的可退余额约束。
- 状态机：`accepted → processing → review → resolved`，其中 `review → processing` 可回退，`processing → resolved` 与 `review → resolved` 均可；`resolved` 与 `revoked` 为终态，终态不可再推进。
- 撤销关闭：进行中（accepted/processing/review）可撤销，仅释放处理中标记、不扣减金额；`resolved` 可撤销一次，把裁决金额加回退款单金额并恢复其生效扣减，工单进入 `revoked` 终态，工单与退款单两侧同事务原子生效。
- 裁决扣减：推进到 `resolved` 时携带裁决金额（正整数），须不超过处理请求金额且不超过退款单当前金额，超限或非法拒绝且不改数据。成功后退款单金额扣减；若退款单为 `completed`，其生效扣减同步为扣减后金额；订单金额始终不变。
- 当前生效扣减：`resolved` 工单为裁决金额，其余状态为 0（撤销后清零）。
- 幂等：受理、推进、撤销关闭各自携带 `request_id`；同标识重放返回首次结果（含失败响应），不重复扣减或释放；同标识改作不同操作或对象返回 409。
- 并发：全部写操作在单库 `BEGIN IMMEDIATE` 事务内串行提交；并发冲突的最终结果仍满足金额上限、标记唯一与状态机约束。
- 隔离：单读、列表与全部操作均以 `X-Tenant` 限定；跨租户读取、列出或操作一律按不存在（404）处理。
- 持久化：工单状态、处理中标记、退款单金额与生效扣减全部落库并在事务内一致更新；重启与中断重试后保持一致。
