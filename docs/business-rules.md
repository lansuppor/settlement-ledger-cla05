# 业务规则

## 订单

- 订单以（租户, 订单标识）唯一；重复受理必须被拒绝且不改变已存在单据。
- 未收金额 = 订单金额 − 已收金额；收款不得超过未收金额。
- 跨租户读取一律按“不存在”处理，不得泄漏对象是否存在。
- 金额以最小货币单位的整数表示，不使用浮点数。

## 退款单

- 退款单以（租户, 退款标识）唯一；每张订单可登记多笔退款单。
- 生命周期：`pending`（待审核）→ `approved`（已同意）/ `rejected`（已拒绝）；已同意的退款单可 `reversed`（已冲正）。
- 登记只进入待审核态，不实际退款、不调整订单已收金额；字段为 `tenant`、`refund_id`、`order_id`、`amount_cents`、`reason`，金额必须为大于 0 的整数，原因不可为空白。
- 登记以业务身份（租户, 退款标识）幂等：重复提交不新建单据、不重复退款，忽略请求指纹差异，返回既有单与其当前状态（HTTP 200）。
- 待审核退款对订单已收金额形成预留：同一订单全部待审核退款之和不得超过当前已收金额，否则登记返回冲突。
- 只有审核同意才对订单生效：已收金额减少、未收金额等额增加，未收始终等于订单金额减已收金额；审核拒绝不改变订单。
- 审核同意后，已生效退款与其他待审核预留之和不得超过当前已收金额；任何时刻已收金额都在 0 与订单金额之间。
- 审核结果不可被后续审核覆盖：对已同意/已拒绝的退款单重复审核，返回原结果且不改数据。
- 显式冲正（撤销）只作用于指定退款单：把该笔已生效退款全额反向退回订单，恢复已收与未收，单据置为已冲正；待审核、已拒绝、已冲正的单据冲正一律被拒绝且不改变数据；已冲正的单据不得再次审核。
- 读取、审核、冲正均要求请求头 `X-Tenant`；跨租户操作一律按“不存在”处理（404），不泄漏对象是否存在，也不得作用于其他租户的单据。
- 失败可判定：参数问题（字段缺失/非法、订单不存在或非本租户）为 400；金额守恒或状态冲突为 409；对象不存在为 404；均区别于 5xx。任何失败都不留半张单据或半次金额调整。
- 所有登记、审核、冲正都在单事务内完成并对数据库加写锁；并发登记同一退款标识最终只有一张单据，审核与冲正交错后订单金额必然闭合，且状态与金额持久保存，服务重启后结论一致。
