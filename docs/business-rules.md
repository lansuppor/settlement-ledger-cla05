# 业务规则

## 订单与收款

- 订单以（租户, 订单标识）唯一；重复受理必须被拒绝且不改变已存在单据。
- 未收金额 = 订单金额 − 已收金额；收款不得超过未收金额。
- 跨租户读取一律按“不存在”处理，不得泄漏对象是否存在。
- 金额以最小货币单位的整数表示，不使用浮点数。

## 订单批量受理

### 批次身份与幂等

- 批量受理以（租户, 批次标识 `batch_id`）为业务身份，与单个订单标识、CSV 行内容均无关。
- 同一租户下相同 `batch_id` 视为同一批次的重试：不新建批次、不重复受理任何订单，只返回该批次既有处理结果与计数（HTTP 200）；即使重放时行内容不同，也不新建批次、不按新行受理。
- 批次中出现已受理订单（单笔受理、批次内前序行或其他批次已受理）时，按既有订单处理：不重复受理、不改变其金额与币种，该行记为订单冲突，与参数错误区分。

### CSV 与逐行校验

- CSV 首行必须为表头 `tenant,order_id,amount_cents,currency`，其后每行一笔订单，字段口径与单笔受理一致。
- 每行独立校验：行内 `tenant` 必须与请求声明的租户一致；`order_id` 非空；`amount_cents` 为大于 0 的最小货币单位整数；`currency` 为受支持币种。任一不满足该行记为参数错误。
- 校验失败的行不受理，带物理行号记入错误清单；其余行正常受理。批次结果恒有 成功数 + 失败数 = 总数。
- 批次结果含 `batch_id`、`status`、`total`、`success_count`、`failure_count`、`errors`、`accepted_order_ids`；错误清单项含 `line_no`、`code`（`invalid_param` / `order_conflict`）、`message`。
- 全部成功时状态为 `completed`；存在失败行时为 `completed_with_errors`。

### 整批拒绝

- CSV 格式非法（缺表头、表头不符、数据行列数与表头不符、UTF-8 编码非法、引号等行结构损坏）时整批拒绝，返回参数错误（400）且不受理任何行、不创建批次。
- 格式合法但个别行业务校验失败时，只跳过该行，其余行正常受理。

### 中断续跑

- 每行的订单写入与批次行结果、已处理计数在同一数据库事务内提交：服务停止或请求中断后，已提交的行不回滚，未处理的行不会遗留半张单据。
- 用同一 `batch_id` 重新提交即从断点继续（续跑以首次提交并存档的 CSV 为准），最终结果与一次连续处理完全一致：状态、计数、错误行号、已受理订单列表均闭合，且不受中断点影响；同一行最多产生一张订单。
- 两种终态（`completed`、`completed_with_errors`）下重放同一 `batch_id` 都不再改变任何订单。

### 租户隔离

- 行内租户与请求声明租户不一致的行按参数错误计入错误清单，不受理。
- 批次查询须经请求头 `X-Tenant` 声明租户；跨租户读取或续跑批次一律按“不存在”（404）处理，不泄漏批次是否存在，且不得作用于其他租户的批次与订单。

## 退款单

### 唯一性与登记

- 退款单以（租户, 退款标识 `refund_id`）唯一；同一订单可登记多笔退款单。
- 登记字段：`tenant`、`refund_id`、`order_id`、`amount_cents`、`reason`；金额必须是大于 0 的最小货币单位整数，原因为必填。
- 登记成功后退款单进入 `pending`（待审核）态，此时尚未实际退款，不调整订单金额。
- 重复登记以业务身份（租户 + `refund_id`）为准，与请求指纹无关：重复提交不新建单据、不重复退款，返回既有退款单及当前状态（HTTP 200）。
- 登记到不存在或非本租户的订单、金额非法、原因缺失，返回参数错误（400）。

### 审核

- 审核决定 `approve`（同意）或 `reject`（拒绝）；只有同意才对订单生效。
- 生效退款总额（已批准未冲正）在任何时刻不得超过该订单的累计已收金额：
  - 登记时，待审核与已生效退款合计加本笔不得超过订单当前已收金额，否则返回冲突（409）；待审核金额视为已占用额度。
  - 审核同意时再次防御性校验，若生效会造成退款超出已收金额，返回冲突（409）且不改变任何数据。
- 审核结果不可被后续审核覆盖；重复审核返回原结果。
- 同意生效后，订单对外已收金额扣减该笔金额，未收金额 = 订单金额 − 已收金额随之回升；已收金额始终落在 [0, 订单金额]。

### 冲正（撤销）

- 冲正只作用于指定退款单，将该笔已生效退款全额反向退回订单，恢复订单已收与未收金额，并把退款单置为 `reversed`（终态）。
- 仅 `approved` 的退款单可冲正；待审核、已拒绝、已冲正的退款单执行冲正均返回冲突（409）且不改变任何数据。
- 冲正后不得再次审核。
- 若该笔退款腾出的额度已被后续收款补回，冲正会使已收金额超过订单金额，此时拒绝冲正（409），保持账务闭合。

### 租户隔离

- 读取、审核、冲正都必须在请求头 `X-Tenant` 传入租户。
- 跨租户读取、审核、冲正一律按“不存在”（404）处理，不泄漏对象是否存在，且审核、冲正不得作用于其他租户的退款单。

### 失败、并发与持久化

- 参数错误（400）、冲突（409）、对象不存在（404）相互区分，均不同于内部错误（500）。
- 任何失败都不留下半张单据或半次金额调整：单据写入、状态迁移与金额检查在同一数据库事务内完成。
- 并发登记同一退款标识、并发审核同一退款单，最终只有一张单据、一次金额调整（写事务以 `BEGIN IMMEDIATE` 串行化）。
- 审核与冲正任意交错后账务闭合：订单金额 = 已收金额 + 未收金额，且已收金额始终在 0 与订单金额之间。
- 退款单状态、订单金额与冲正结果均持久化在数据库中，服务重启后查询结论一致、规则继续生效。
