# 业务规则

## 订单与收款

- 订单以（租户, 订单标识）唯一；重复受理必须被拒绝且不改变已存在单据。
- 未收金额 = 订单金额 − 已收金额；收款不得超过未收金额。
- 已收金额按净额呈现：累计收款扣减已生效（批准且未冲正）退款，收款回退等额调减累计收款；已收金额始终落在 [0, 订单金额]。
- 跨租户读取一律按“不存在”处理，不得泄漏对象是否存在。
- 金额以最小货币单位的整数表示，不使用浮点数。

## 订单批量受理

### 批次身份

- 批量受理以（租户, 批次标识 `batch_id`）为业务身份；导入请求必须声明 `tenant` 与 `batch_id`。
- 批次身份与单个订单标识是两回事：同一租户下相同 `batch_id` 即同一批次的重试，与 CSV 行内容无关，不因行内容不同而新建批次。
- 同一批次重放不重复受理任何订单，只返回该批次既有处理结果与计数（HTTP 200）；首次处理返回 201。
- 批次结果可按 `batch_id` 查询（`GET /batches/{batch_id}`），查询必须在请求头 `X-Tenant` 传入租户；跨租户查询或续跑一律按“不存在”（404）处理，不泄漏批次是否存在。

### CSV 格式

- 表头必须恰为 `tenant,order_id,amount_cents,currency`，字段含义与单笔受理一致；数据为 UTF-8 文本。
- CSV 格式非法——缺表头、列数不符、编码非法、行结构损坏（如引号未闭合）——整批拒绝，返回参数错误（400），不产生批次、不受理任何行。
- 格式合法但个别行业务校验失败时只跳过该行，不影响其余行。

### 逐行校验与部分成功

- 每行独立校验：行内 `tenant` 必须与请求声明的租户一致、`order_id` 非空、`amount_cents` 为大于 0 的最小货币单位整数、`currency` 为受支持币种；任一不满足该行不受理，带物理行号记入错误清单。
- 参数错误（`invalid_parameter`）与订单冲突（`order_conflict`）通过错误清单中的 `error_code` 区分。
- 批次中出现已受理订单（此前单笔/其他批次受理，或本批次内重复标识）时按既有订单处理：不重复受理、不改变其数据，以 `order_conflict` 记入错误清单；同一行最多产生一张订单。
- 批次结果含 `batch_id`、`status`、`total`、`succeeded`、`failed`、错误清单与已受理订单标识列表；恒有 成功数 + 失败数 = 总数。
- 有失败行时状态为 `completed_with_errors`（带错误完成），全部成功时为 `completed`（已完成，含空文件）。

### 中断与续跑

- 每行在独立数据库事务内提交（订单写入与该行结果记录同事务）：处理中途服务停止或请求中断后，已提交的行不回滚，未处理的行不遗留半张单据。
- 用同一 `batch_id` 与同一份输入重新提交即从断点继续：已记录结果的行（成功或失败）跳过，只处理未落库的行，最终结果与一次连续处理完全一致，计数闭合，不受中断点影响。
- 进行中批次只接受同一份输入（字节一致、行数一致）续跑；以不同输入续跑返回冲突（409）。
- 批次进入终态（`completed` / `completed_with_errors`）后，无论用什么输入重放同一 `batch_id` 都不再改变任何订单，只回放既有结果。
- 受理成功的订单沿用单笔受理的字段与金额口径，之后可按现有接口读取、登记收款；既有订单受理、读取、收款与退款单行为不受批量路径影响。

## 退款单

### 唯一性与登记

- 退款单以（租户, 退款标识 `refund_id`）唯一；同一订单可登记多笔退款单。
- 登记字段：`tenant`、`refund_id`、`order_id`、`amount_cents`、`reason`；金额必须是大于 0 的最小货币单位整数，原因为必填。
- 登记成功后退款单进入 `pending`（待审核）态，此时尚未实际退款，不调整订单金额。
- 重复登记以业务身份（租户 + `refund_id`）为准，与请求指纹无关：重复提交不新建单据、不重复退款，返回既有退款单及当前状态（HTTP 200）。
- 登记到不存在或非本租户的订单、金额非法、原因缺失，返回参数错误（400）。

### 审核

- 审核决定 `approve`（同意）或 `reject`（拒绝）；只有同意才对订单生效。
- 生效退款总额（已批准未冲正）在任何时刻不得超过该订单的累计已收金额：
  - 登记时，待审核与已生效退款合计加本笔不得超过订单当前已收金额，否则返回冲突（409）；待审核金额视为已占用额度。
  - 审核同意时再次防御性校验，若生效会造成退款超出已收金额，返回冲突（409）且不改变任何数据。
- 审核结果不可被后续审核覆盖；重复审核返回原结果。
- 同意生效后，订单对外已收金额扣减该笔金额，未收金额 = 订单金额 − 已收金额随之回升；已收金额始终落在 [0, 订单金额]。

### 冲正（撤销）

- 冲正只作用于指定退款单，将该笔已生效退款全额反向退回订单，恢复订单已收与未收金额，并把退款单置为 `reversed`（终态）。
- 仅 `approved` 的退款单可冲正；待审核、已拒绝、已冲正的退款单执行冲正均返回冲突（409）且不改变任何数据。
- 冲正后不得再次审核。
- 若该笔退款腾出的额度已被后续收款补回，冲正会使已收金额超过订单金额，此时拒绝冲正（409），保持账务闭合。

### 租户隔离

- 读取、审核、冲正都必须在请求头 `X-Tenant` 传入租户。
- 跨租户读取、审核、冲正一律按“不存在”（404）处理，不泄漏对象是否存在，且审核、冲正不得作用于其他租户的退款单。

### 失败、并发与持久化

- 参数错误（400）、冲突（409）、对象不存在（404）相互区分，均不同于内部错误（500）。
- 任何失败都不留下半张单据或半次金额调整：单据写入、状态迁移与金额检查在同一数据库事务内完成。
- 并发登记同一退款标识、并发审核同一退款单，最终只有一张单据、一次金额调整（写事务以 `BEGIN IMMEDIATE` 串行化）。
- 审核与冲正任意交错后账务闭合：订单金额 = 已收金额 + 未收金额，且已收金额始终在 0 与订单金额之间。
- 退款单状态、订单金额与冲正结果均持久化在数据库中，服务重启后查询结论一致、规则继续生效。

## 收款回退

### 业务身份与请求

- 收款回退用于收款登记后发现收错或重复收款时反向退回已收金额，与退款冲正共同构成账务闭环。
- 回退以（租户, 回退标识 `rollback_id`）为业务身份；请求须声明 `tenant`、`rollback_id`、所属订单 `order_id` 与回退金额 `amount_cents`（大于 0 的最小货币单位整数）。
- 登记接口 `POST /payment-rollbacks` 首次生效返回 201；读取接口 `GET /payment-rollbacks/{rollback_id}` 需在请求头 `X-Tenant` 传入租户。

### 幂等

- 是否重复以业务身份（租户 + `rollback_id`）判定，与请求指纹（金额、订单等字段）不能混为一谈。
- 相同业务身份重复请求不新建回退记录、不重复退回金额，返回既有回退结果（HTTP 200）；重复请求中声明的金额、订单与首次不一致时一律忽略，以首次生效内容为准。
- 首次请求因校验失败未生效（未写入记录）时，不占用业务身份，可用同一身份修正参数后重试。

### 金额规则

- 回退记录写入与订单累计收款调减在同一数据库事务内完成：任何失败都不留下半张回退单据或半次金额调整。
- 回退后订单对外已收金额按净额重新计算（累计收款 − 已生效未冲正退款），未收金额仍等于订单金额 − 已收金额，已收金额始终落在 [0, 订单金额]，并恒有 订单金额 = 已收金额 + 未收金额。
- 回退腾出的未收额度可再次按既有收款接口登记补齐。
- 一笔订单可按不同 `rollback_id` 多次回退，累计受下述额度约束。

### 与退款额度口径相容

- 退款占用额度与退款登记口径一致：待审核（`pending`）与已生效未冲正（`approved`）退款合并计入占用。
- 回退后退款占用额度不得超过回退后的订单已收金额：
  - 本笔回退金额超过订单当前已收金额（净已收），返回参数错误（400）。
  - 本笔未超过当前已收、但会使退款占用额度超过回退后已收金额（即超出「累计收款 − 退款占用」的剩余可回退额度），返回冲突（409）且不改变任何数据。
- 拒绝退款释放占用额度后，原被冲突挡住的回退可重新提交；回退后退款仍按原规则登记、审核与冲正。

### 交错执行与闭合

- 收款回退与退款审核、冲正可任意交错：回退调减累计收款，冲正把已生效退款全额加回，二者都不改写对方单据。
- 任意交错序列结束后账务必须闭合：订单金额 = 已收金额 + 未收金额，且已收金额始终在 0 与订单金额之间。

### 租户隔离、失败与持久化

- 对不存在或非本租户的订单执行回退，统一按参数错误（400）处理，不泄漏订单是否存在；跨租户读取回退结果按不存在（404）处理。
- 参数错误（400）、冲突（409）、对象不存在（404）相互区分，均不同于内部错误（500）。
- 并发提交同一回退标识最终只有一条记录、一次金额调整；并发提交不同标识的回退共享同一订单的剩余可回退额度，写事务以 `BEGIN IMMEDIATE` 串行化，超额者返回 400 或 409。
- 回退记录与订单金额均持久化在数据库中，服务重启后查询结论一致、幂等与额度规则继续生效。
